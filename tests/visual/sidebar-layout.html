Sidebar layout — mobile crush reproduction & fix verification

Static repro, no browser automation. Each box below is an <iframe> given a fixed pixel width via CSS — that width is the iframe's own viewport for media-query purposes, independent of this window's size, so mobile vs. desktop renders correctly no matter how you view this file. Rows 1–2 use markup and WordPress-generated CSS captured verbatim from a real HAR of the live site (see comments in each fixture file for exact source). Row 3 is a sanity check derived from WordPress core source, not a live capture — see its fixture files for why.

1. BEFORE — v2.0.2 (root cause: body .is-layout-flex beats .site-main__inner on specificity)

Mobile · 390px Expected: broken. Sidebar takes the full row width (width:100% under nowrap flex); content column is crushed to a sliver, text breaks mid-word — this is the reported bug.
Desktop · 1440px Looks fine here — display:grid never applied at any width, but at this width the flex row still happens to read as two columns, which is why the bug went unnoticed.

2. AFTER — fixed (links the real, current assets/css/layout.css)

Mobile · 390px Expected: fixed. Content column full width, sidebar stacks below it, no crushed text.
Desktop · 1440px Expected: fixed. True CSS grid, two columns, sidebar a fixed 350px track, content fluid.

3. Sanity check — flow variant (what the edited templates render; not independently verified against a live capture)

Desktop · 1440px Confirms the fix's margin-block: 0 reset neutralizes flow layout's margin-based gap model (a stray top margin on the sidebar), derived from WordPress core source rather than a captured page. See fixtures/wp-generated-flow.css for the derivation. Should render identically to row 2's desktop panel.

How to read a failure

If row 2 ever regresses to look like row 1, someone changed assets/css/layout.css in a way that dropped the .wp-block-group specificity qualifier (see the comments in that file) — re-open this harness before shipping. fixtures/before-layout.css is a frozen snapshot and must never be edited; if it needs to change, the bug it demonstrates has changed too.
